## 是什么

一个只解决一件事的网页：点一下，随机抽一道今天吃的。

清单自己维护——菜名必填，类别可以自己写（家常菜 / 面食 / 快餐 / 饮品 / 小吃…），图片可选，没图就用菜名生成一个色块占位。抽到的菜会自动进入「本次已排除」和「最近抽到」，避免连着三天吃同一碗面。

## 技术是怎么搭的

单文件 HTML，样式和脚本都内联，双击就能跑，也能直接丢上 GitHub Pages。

- **数据**：整个清单存 `localStorage`，不上传、不登录、无接口。
- **图片**：本地上传的图在写入前用 canvas 压到 900px 以内再转 base64 存本地，顺便解决「一部手机存十张原图就满」的问题；也支持直接粘贴图片链接。
- **无图兜底**：用菜名做稳定哈希生成色块 + 菜名首字，保证同一个菜每次颜色一样。
- **迁移**：导出 / 导入 JSON，换设备时把清单搬过去；「清空全部」走二次确认弹窗，不给你手滑的机会。
- **抽取逻辑**：在「未被排除」的集合里等概率抽，全部排除后自动恢复，不会把用户卡死在「没有可选项」。

## 踩到的坑

- **base64 会撑爆存储**：一开始直接存原图，几张就顶到 5MB 上限。改成上传即压缩之后才稳定。
- **色块颜色乱跳**：用随机数取色，刷新一次整个清单换个样；改成按菜名哈希才固定下来。
- **抽完还要能反悔**：只做「排除」不做「全部恢复」的话，一轮抽完页面就空了，所以补了一个恢复入口。
