## 是什么

海龟汤的规则很简单：给你一段「汤面」（离奇的事件），你只能问是非题，出题人只回答「是 / 否 / 无关 / 无法回答」，最后靠推理说出「汤底」。

这个版本把出题人换成了程序。题库里几道经典题，玩家一句一句问，程序一句一句答；猜中了会有判定，卡住了可以要提示，也可以放弃直接看汤底。

## 技术是怎么搭的

三个原生 JS 文件，没有框架、没有构建、没有依赖：

- **`data.js`**：题库内联（汤面 / 汤底 / 关键词 / 难度 / 提示）
- **`ghpages.js`**：本地判定引擎，IIFE 暴露一个全局对象
- **`app.js`**：交互、渲染、存档、移动端键盘

**判定不是「问 AI」，是一条规则链：**

1. 先过一遍**受控词白名单**：识别出「直接要答案」「让我扮演角色」「要求忽略或复述规则」「要提示」这四类，一律回「无法回答」，不陪聊。
2. 再走**关键词匹配**：把玩家的问题跟本题的关键词表比对，命中则给「是 / 否」。
3. 没命中时算**相似度**，超过阈值算「接近」，否则「无关」。
4. 玩家直接说出接近汤底的句子，判定为猜对。

之所以不用大模型：GitHub Pages 没有后端，API Key 只能写在浏览器里，等于公开。所以把「出题人」做成确定性规则，牺牲一点灵活度，换一个能公开部署的版本。

## 踩到的坑

- **汤底是明文**：题库内联在 `data.js` 里，任何打开网页的人都能看到答案。这是纯前端方案的固有取舍，写在文件头部备忘里。
- **两套判定会漂移**：本地版和原先的后端版规则要人工同步，改动时两边都得改，否则同一个问题两个版本答案不一样。
- **存档写不进去**：隐私模式下 `localStorage` 会抛错，必须 try/catch 兜住，不然整局游戏卡住。
- **移动端键盘**：输入框聚焦后键盘顶起页面，提问按钮被遮住——用了滚动到可视区 + 收起键盘的时序处理。
