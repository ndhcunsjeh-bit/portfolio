## 一句话结论

工具类小页面的价值不在功能多，而在**「打开 → 点一下 → 得到结果」中间没有多余的一步**。

## 原计划 vs 实际

- **功能**：原计划 抽一道菜；实际 抽 + 排除 + 恢复 + 历史
- **图片**：原计划 直接存原图；实际 上传即压到 900px 转 base64
- **数据**：原计划 存浏览器；实际 存浏览器 + 导出 / 导入 JSON
- **部署**：原计划 本地打开；实际 GitHub Pages，单文件

## 做对了

- **抽完自动进「本次已排除」。** 不加这条，第二抽大概率还是同一碗面，工具立刻失去意义。
- **全部排除后自动恢复。** 不然清单抽空，页面变成一个死页面。
- **无图兜底用菜名哈希色块。** 没照片的菜也有稳定颜色，列表不会花。
- **导出 / 导入。** 换手机时不用重新录一遍。

## 做错了

- **图片直接存原图**，第三张就超限，后来才加上传即压缩。
- **色块用随机色**，刷新一次整个清单换个样，看着像坏了。
- **清空没有二次确认**，差点把自己录的半年的清单点没了。

## 下次改

1. 涉及图片的本地应用，写入前先压缩，别等报错才想起来。
2. 任何「删除 / 清空」都要有确认，且默认不选中的那个按钮是危险的。
3. 给「空状态」写一句人话，比放一张插图有用。
